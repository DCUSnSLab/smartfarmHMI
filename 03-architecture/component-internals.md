# 03-4 · 컴포넌트 내부 구성

`component-mapping.md`가 "기능(FR) 하나가 어느 컴포넌트 몫인지"를 다룬다면, 본 문서는 **컴포넌트 하나(웹앱/애플리케이션 서버/미들웨어 서버/엣지) 내부가 어떤 모듈로 이뤄지는지**를 다룬다.

## 1. 웹앱 (프론트엔드)

| 모듈 | 내용 |
|---|---|
| 화면(페이지) | 로그인, 모니터링 대시보드, 로봇/생육기 제어 화면, 데이터 관리(통계·조회·일지·메모), 음성/LLM UI, 장비 관리(등록/삭제) |
| 실시간 데이터 클라이언트 | WebSocket 구독, 수신한 최신 데이터로 화면 갱신 |
| API 클라이언트 | REST 호출(조회·설정 변경), 애플리케이션 서버만 호출 (미들웨어 서버·엣지에는 직접 접근하지 않음) |
| 인증 상태 관리 | 로그인 토큰 보관, 라우트 가드(권한별 화면 접근 제어) |

## 2. 애플리케이션 서버

| 모듈 | 내용 |
|---|---|
| API 계층 (라우터/컨트롤러) | REST 엔드포인트, WebSocket 게이트웨이(웹앱에 데이터 푸시) |
| 인증/권한 모듈 | 로그인, 세션/토큰 발급·검증, 역할별 권한 검사 |
| 비즈니스 로직 (서비스) | 메모 관리(FR-18), 장비 등록·관리(FR-07·13) — 사용자가 직접 입력하는 내용 처리 |
| 미들웨어 서버 클라이언트 | 통계·리포트·AI 분석·음성/LLM 결과 조회 요청, 제어 명령 전달 요청 (애플리케이션 서버는 엣지와 직접 통신하지 않는다) |
| 자체 저장소 | 계정, 세션, 메모 첨부파일 등 — 엣지 원시 데이터·통계·AI 분석 결과는 여기 두지 않는다 |

## 3. 미들웨어 서버

| 모듈 | 내용 |
|---|---|
| 엣지 통신 어댑터 | 엣지와의 프로토콜 처리. 2차년도는 임의 데이터 생성기, 이후 실제 엣지 구현체로 교체 |
| 데이터 수집기 | 센서·로봇 상태 수신, 시간 동기화, DB 적재 |
| 커맨드 변환기 | 애플리케이션 서버로부터 받은 제어 요청을 엣지가 이해하는 명령으로 변환해 전달 |
| 통계·리포트 엔진 | 저장된 원시 데이터로 통계 집계(FR-14), 농업일지 생성(FR-17) |
| AI·음성 연동 모듈 | 영상 기반 AI 분석(FR-09·12), 음성 인식/LLM 연동 훅(FR-27~30) — 엔진 자체는 미구현, 호출·결과 수신만 |
| 데이터 저장소 (DB) | 시계열 센서 데이터, 로봇 상태, 파레트·작업 임무 기록 |
| 내부 조회 API | 애플리케이션 서버가 호출하는 API (외부 공개 없음) |

## 4. 엣지 (2차년도 한정 — 임의 데이터 생성기)

> **이 컴포넌트는 2차년도에 한정된 임시 구현이다.** 실제 엣지 실물이 없어 우리가 그 자리를 대신하는 시뮬레이터를 만드는 것이며, 실제 엣지(로봇·센서 실물, 3차년도 예정)의 개발은 우리 책임이 아니다. 미들웨어 서버가 노출하는 엣지 통신 인터페이스를 그대로 따르므로, 실제 엣지가 준비되면 이 컴포넌트를 통째로 교체하기만 하면 된다.

| 모듈 | 내용 |
|---|---|
| 센서 데이터 생성기 | 온도·습도·조도·전력·탱크 수위 등 값을 주기적으로 생성해 미들웨어 서버로 전송 (랜덤 또는 패턴 기반, 필요시 이상값도 생성) |
| 로봇 상태 생성기 | 위치·속도·전원·이상여부를 주기적으로 생성해 전송 |
| 파레트 임무 응답 시뮬레이터 | 미들웨어 서버가 보낸 파레트 작업 임무(FR-03, FR-19~26)를 받아, 일정 시간 뒤 "완료"(또는 의도적 실패) 응답을 돌려준다 |
| 통신 인터페이스 | 미들웨어 서버와 동일한 메시지 스키마(`communication-interface.md`) 사용 |
