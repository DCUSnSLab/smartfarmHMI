# 03-1 · 시스템 아키텍처

## 1. 계층 구조

```
┌────────────────────┐     ┌─────────────────────────┐      ┌────────────────────┐
│  웹앱 (프론트엔드)   │     │   서버 (미들웨어)         │      │   엣지              │
│                    │     │                         │      │                    │
│  모니터링 대시보드   │     │  데이터 수집·저장          │      │  (2차년도)          │
│  제어 UI           │<==> │  제어 명령 변환·출력       │ <==> │  임의 데이터 생성기   │
│  데이터 관리        │     │  농업일지 엔진             │     │                     │
│  음성/LLM UI       │     │  REST/API · 인증         │      │  (3차년도 예정)      │
│                    │     │  외부 AI/음성/LLM 연동 훅 │      │  실제 엣지           │
└────────────────────┘     └─────────────────────────┘      └────────────────────┘
```

엣지 하위의 로봇·생육기 등 실물 하드웨어, 로봇 경로계획, AI 모델, 음성 인식 엔진은 개발 범위 밖이다.

## 2. 계층별 동작 방식

각 계층에 무엇이 있는지는 위 다이어그램을 참고하고, 여기서는 계층 간 동작 방식만 다룬다.

### 웹앱 ↔ 서버
- 화면 갱신은 WebSocket으로 서버가 푸시하는 최신 데이터를 받는다.
- 설정 변경·조회는 REST로 처리한다.

### 서버
- 엣지가 주기적으로 전송하는 데이터를 수신·저장한다. 센서값 하나하나를 즉시 웹앱까지 중계하는 것이 아니라, 서버가 중간에서 저장·버퍼 역할을 한다.
- 저장된 최신 데이터는 웹앱에 푸시하고, 과거 데이터는 REST 조회로 제공한다.
- 웹앱의 제어 요청을 규격화된 명령으로 변환해 엣지로 전달한다.
- 외부 AI·음성·LLM 엔진 연동은 호출과 결과 수신 훅만 구현한다 (엔진 자체는 미구현).

### 엣지
- 2차년도에는 임의 데이터 생성기로 대체한다. 데이터를 주기적으로 서버에 전송하고, 서버의 제어 명령을 받아 실행하는 역할을 한다.

## 3. 설계 원칙

1. 모든 외부 하드웨어는 엣지를 통해서만 서버와 통신한다.
2. 엣지와의 통신은 인터페이스로 분리한다. 2차년도에는 임의 데이터 생성기 구현체를 연결하고, 이후 실제 엣지 구현체로 교체 가능해야 한다 (아래 구조 참고).
3. 데이터·명령 규격은 특정 필드 집합에 고정하지 않고, 확장 가능한 구조로 설계한다.

```
서버 코어 (데이터 수집/제어 명령 로직)
        │
        ▼
  엣지 통신 인터페이스
        │
        ├── 2차년도:  임의 데이터 생성기 구현체
        └── 3차년도:  실제 엣지 구현체 (예정)
```
