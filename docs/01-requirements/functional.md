# 01-1 · 기능 요구사항

## 0. 표기 규칙

- 기능 ID: `FR-<번호>`
    - **FR-01 ~ FR-31**: 사업단이 제공한 "스마트팜HMI기능설계" 문서의 번호와 동일하다. **번호를 재배치하지 않는다.**
    - **FR-32 이후**: 요구사항 정합화 과정에서 자체 도출한 기능이다. 디자인 프로토타입이 이미 화면으로 구현했으나 대응 요구사항이 없던 항목과, 통신 규격 확정(MQTT)으로 새로 필요해진 항목이다.
- **담당 영역**:

    - `HMI`(애플리케이션 서버+웹앱이 직접 구현)
    - `엣지`(제어·판단 로직, 개발 범위 밖 — 결과만 수신)
    - `외부`(엣지가 아닌 외부 시스템에 의존 — 기상 API, 음성 엔진, LLM 등)
    - `공통`(HMI와 엣지가 나눠서 담당)
    - "공통"의 기본 분담은 **설정·표시는 HMI, 실행은 엣지**이며, 이 기본형에 해당하는 항목은 비고에 다시 풀어 설명하지 않는다. 기본형과 다르게 나뉘는 경우(예: 수집은 엣지·표시는 HMI처럼 설정/실행이 아닌 다른 축으로 나뉘는 경우)만 비고에 구체적으로 명시한다.
- **데이터소스**:
    - `SIMULATED`(2차년도는 실물 엣지가 없어 임의 데이터 생성기가 대신 응답)
    - `EXTERNAL`(외부 시스템에서 취득 — 기상 API 등)
    - `N/A`(엣지 시뮬레이션 데이터에 의존하지 않는 기능 — 순수 HMI 관리·입력·플랫폼 기능이거나, 음성·LLM처럼 엣지가 아닌 다른 외부 시스템에 의존하는 기능)

> 양액·급수·방재는 파이프(관) 배관이 아니라, 로봇이 재배 트레이(파레트)를 랙에서 반출해 작업 장소(양액·급수·방재·수확 스테이션)로 옮기고 작업 후 원래 슬롯에 반납하는 방식(트레이 반출→작업장소 이동→작업→반납)이다.

- 작업 스케줄링(FR-19·FR-20) : 언제, 몇 번 할지(시각·횟수)를 정하는 스케줄 설정
- 양액/급수/방재 설정(FR-21~26) : 얼마나 줄지(양·농도) 설정
- 로봇임무 스케줄링(FR-03) : 실행 시점에 작업 스케줄링과 설정들이 합쳐져 FR-03의 로봇 임무 실행

> **모든 기능은 농장(Farm) 단위로 동작한다.** 설계·구현은 농장 N개를 전제로 하고 2차년도 실운영은 농장 1개다 (`../../00-overview.md` 다농장 전제 참고). 아래 기능 설명에서 "생육기별"·"로봇별"은 모두 특정 농장에 속한 장비를 의미한다.

## 1. 로봇 제어

### FR-01 로봇 작업데이터 로깅
- 설명: 단위작업별 성공 여부 및 작업량 로깅 (적엽, 트레이 반출/이동/반납 등). 수확은 3차년도 범위이며 2차년도 로깅 대상에서 제외한다.
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 작업 이력을 미들웨어 서버가 수신·저장하고, 웹앱은 애플리케이션 서버를 통해 조회한다. **재시도 횟수를 함께 기록한다** — 단위작업이 1회 이상 재시도 후 성공한 경우를 성공/실패와 구분해 조회할 수 있어야 한다 (`RobotTaskLog.retry_count`).

### FR-02 다중 로봇 제어
- 설명: 군집 제어 및 이종 로봇 제어
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 웹앱은 제어 요청 UI만 제공하고, 미들웨어 서버가 명령을 규격화해 엣지로 전달한다. 다중 로봇 제어 자체를 우리가 담당할지, 엣지팀이 전담할지는 아직 정해지지 않았다 (OPN-13). 담당 여부가 확정되기 전까지 웹앱에 군집 제어 UI를 만들지 않는다.

### FR-03 로봇임무 스케줄링
- 설명: 각 로봇의 시간별 운반경로 지정 (트레이 반출 위치, 작업 장소, 반납 위치)
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 임무 등록·조회 UI를 제공하고 미들웨어 서버가 저장한다. FR-19·FR-20, FR-21~26이 실행 시점에 이 임무로 이어진다.
- **충돌 검사**: 임무 등록 시 아래 세 가지 자원의 시간 충돌을 모두 검사한다. 충돌 시 등록을 거부하고, 「기존 임무 삭제 후 추가」 또는 「기존 임무 종료 후로 예약」을 선택하게 한다.
    1. **로봇** — 같은 로봇이 동시에 두 임무를 수행할 수 없다
    2. **워크스테이션** — 같은 워크스테이션에서 동시에 두 작업을 수행할 수 없다
    3. **파레트** — 같은 파레트가 동시에 두 임무의 대상이 될 수 없다

### FR-04 로봇상태 모니터링
- 설명: 로봇 위치, 속도, 전원, 이상여부 주기적 모니터링
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: 충전 중 여부와 현재 임무 진행 상태(대기/이동중/작업중)를 함께 표시한다. 로봇 위치는 실시간 배치도(FR-41)에도 반영된다.

### FR-05 로봇 센서데이터 로깅
- 설명: 로봇 영상데이터 로깅 (생육상태 판별용)
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 영상 메타데이터를 수신·저장하고 조회 UI를 제공한다. 원본 영상은 목데이터로 대체한다. **조회 UI는 목록·재생(또는 대표 프레임) 화면까지 포함한다** — 진입 버튼만 두는 것으로는 요구사항을 충족하지 않는다.

### FR-06 로봇 자동충전기능
- 설명: 로봇 자동충전 지시, 다중 로봇 운용 시 충전 스케줄링
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 웹앱은 충전 지시(충전 스테이션 복귀)와 충전 상태·완충 예상 시간 표시를 담당한다.

### FR-07 로봇 추가/삭제 기능
- 설명: 관리 대상 로봇의 추가 또는 삭제
- 담당 영역: HMI
- 데이터소스: N/A
- 비고: **추가와 삭제 모두 UI를 제공한다.** 등록 대상은 로봇에 한정하지 않고 **탱크·워크스테이션·센서**까지 포함한다 (FR-13과 함께 `DeviceMeta` 전체를 관리). 삭제 시 해당 장비의 과거 데이터(작업 이력·센서 이력)는 보존하고 관리 대상에서만 제외한다.

## 2. 생육기 제어

### FR-08 생육환경 모니터링
- 설명: 온도/습도/양분/조도/소모전력, 양액·급수·방재액 탱크 수위 등 주기적 모니터링 (센서 정상작동여부 포함)
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: **"센서 정상작동여부"는 FR-37(통신 상태 감시)로 구현한다** — MQTT LWT/death 메시지와 마지막 수신 시각으로 센서별 온라인·응답지연 상태를 판정한다. 개별 센서의 식별·설치 위치·상태 관리는 FR-39를 따른다. 탱크 수위는 잔량(L)과 사용 가능 기간·횟수 환산값을 함께 표시하며, 환산에는 `Tank`의 용량·소비율이 필요하다.

### FR-09 생육상태 모니터링
- 설명: 영상 기반 생육 상태(성장률, 병충해 유무, 수확시기) 모니터링
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고: 영상 수집은 엣지, 분석 결과 표시는 HMI가 담당한다. AI 분석 자체는 외부 연동 훅으로 처리한다.

### FR-10 생육기 수동제어
- 설명: 생육기의 온도/습도/양분/조도(LED 조명)를 수동 설정값에 맞게 제어
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고: **제어 대상은 온도·습도·양분·조도(LED) 4종으로 한정한다.** 환기·차광·천창 액추에이터는 개발 범위 밖이며(`../../00-overview.md` Out of Scope), 외기 조건에 따른 차광·환기 권고는 제어가 아니라 참고 정보로만 표시한다. LED는 파레트별로 설치되어 있으나, 2차년도는 그룹/전체 단위로 제어하고 개별(파레트별) 제어는 확장 여지로 남긴다 (OPN-14).

### FR-11 생육기 자동제어
- 설명: 성장단계에 맞는 온도/습도/양분/조도(LED 조명) 자동 설정
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 웹앱은 자동 모드 On/Off와 **현재 성장단계 선택**, 결과 확인 UI를 제공한다. 단계별 목표값 산출은 엣지가 담당한다.

### FR-12 AI기반 생육기 제어
- 설명: 생육조건 유지 시 전력효율을 극대화하는 AI 제어
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 웹앱은 설정 UI만 제공하고, AI 판단 로직은 외부 연동 훅으로 처리한다. **설정 UI는 최소한 AI 제어 On/Off와 우선순위(생육조건 우선 ↔ 전력효율 우선) 선택을 포함한다.**

### FR-13 생육기 추가/삭제 기능
- 설명: 관리 대상 생육기의 추가 또는 삭제
- 담당 영역: HMI
- 데이터소스: N/A
- 비고: FR-07과 동일한 장비 등록·관리 화면에서 처리한다. 삭제 UI를 포함한다. 생육기 등록 시 소속 농장과 연결 센서를 함께 지정한다.

## 3. 데이터 관리/생성

### FR-14 데이터 통계 기능
- 설명: 생육기별 시간/일/주/월별 생육환경·생육상태 데이터 통계
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: **생육환경과 생육상태 양쪽 모두 통계 대상이다.** 집계 축은 기간(시간/일/주/월) × 대상(전체 농장 / 특정 농장 / 특정 생육기)이다. 생육기 단위 축의 UI 구성은 보류 상태다 (OPN-16).

### FR-15 데이터 조회 기능
- 설명: 특정 조건에 맞는 데이터 조회
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: 통계(FR-14)와 별개로 **조건 지정 조회 기능**이 필요하다. 조건은 기간·농장·생육기·센서 종류·값 범위를 조합한다. 조회 결과 내보내기(CSV 등)를 포함한다.

### FR-16 데이터 로깅 기능
- 설명: 생육기·로봇·센서 데이터를 시간 동기화하여 저장
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 엣지가 주기적으로 전송한 데이터를 미들웨어 서버가 저장소(DB)에 적재한다. 시간 동기화 기준은 미들웨어 서버 수신 시각이 아니라 **메시지의 `timestamp`(엣지 발생 시각)** 이며, 수신 시각도 함께 보존해 지연을 판정할 수 있게 한다.

### FR-17 농업일지 자동 생성
- 설명: 통계데이터 기반 일/주간/월간/년간 리포트 자동 생성
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: **일간·주간·월간·년간 4종 모두 생성한다.**

### FR-18 관리자 메모 작성 기능
- 설명: 농업일지에 관리자 메모(사진·동영상 첨부 가능) 추가
- 담당 영역: HMI
- 데이터소스: N/A
- 비고: 메모는 날짜와 대상 농장을 지정해 작성한다.

## 4. 작업 스케줄링

### FR-19 수동 스케줄링
- 설명: 생육기별 생육시기에 따른 작업(양액·급수·방재·수확 등)의 1일 횟수와 시간 설정
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고: **표시뿐 아니라 편집(횟수·시각 추가·변경·삭제) UI를 제공한다.** 수확 작업 스케줄은 3차년도 범위다.

### FR-20 자동 스케줄링
- 설명: 생육기별 생육상태를 보고 수행할 작업 자동 설정
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 웹앱은 자동 모드 On/Off와 자동 생성된 스케줄의 조회를 제공한다. 자동 모드에서도 사용자가 결과를 확인할 수 있어야 한다.

## 5. 양액 · 급수 · 방재 제어

> 작업 장소에서 적용할 양·농도 등 파라미터를 의미한다. 양액/급수/방재액은 트레이 반출 방식이 동일해 수동설정 3종을 모두 "공통"으로 통일한다.

### FR-21 양액 수동설정
- 설명: 생육기별 생육시기에 따른 양액량 수동설정
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고: 회당 양액량과 농도(EC)를 설정한다.

### FR-22 양액 자동설정
- 설명: 생육기별 현재 생육상태에 맞는 최적 양액량 자동 설정
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: 웹앱은 자동 모드 On/Off와 자동 산출된 설정값 조회를 제공한다.

### FR-23 급수 수동설정
- 설명: 생육기별 생육시기에 따른 급수량 수동설정
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고: **양액(FR-21)과 동등한 수준의 설정 UI가 필요하다** — 회당 급수량 설정 항목을 제공한다.

### FR-24 급수 자동설정

- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: FR-22와 동일한 방식으로 처리한다.

### FR-25 방재액 수동설정

- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고: **양액(FR-21)과 동등한 수준의 설정 UI가 필요하다** — 회당 방재액량과 농도 설정 항목을 제공한다.

### FR-26 방재액 자동설정
- 설명: 생육기별 현재 생육상태에 맞는 최적 방재액량 자동 설정
- 담당 영역: 엣지
- 데이터소스: SIMULATED
- 비고: FR-22와 동일한 방식으로 처리한다.

## 8. 알림

> 임계 초과·장비 이상·통신 단절·작업 완료를 사용자에게 전달하는 도메인이다. 디자인 프로토타입이 화면 2개와 전역 패널·설정 섹션으로 이미 구현했으나 대응 요구사항이 없어 신설했다.

### FR-32 알림 생성
- 설명: 아래 조건 발생 시 알림을 생성한다.
    - 센서값 임계 초과·근접 (예: 내부온도 상한 근접)
    - 탱크 잔량 부족
    - 장비 이상 (로봇 오류, 센서 이상)
    - **통신 단절** (FR-37이 감지한 장치 오프라인)
    - 정지 발생·해제 (FR-35·36)
    - 작업 완료·실패
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: 미들웨어 서버의 알림 엔진이 수집 데이터와 알림 규칙(FR-34)을 대조해 생성한다. 심각도는 **경고 / 주의 / 완료** 3단계다. 임계값 기본값과 에스컬레이션 정책은 미정 (OPN-20).

### FR-33 알림 조회·확인 처리
- 설명: 전체 농장 또는 특정 농장의 알림을 조회하고 확인 처리한다.
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: 심각도별 필터, 미확인 건수 표시, 개별·일괄 읽음 처리, **관련 화면으로의 딥링크**(예: 탱크 잔량 알림 → 해당 농장 작업·공급 화면)를 제공한다. 알림 엔터티는 딥링크 대상을 갖는다.

### FR-34 알림 규칙 설정
- 설명: 알림 종류별 수신 여부와 임계값을 설정한다.
- 담당 영역: HMI
- 데이터소스: N/A
- 비고: 농장별로 설정할 수 있어야 한다. 최소 단위는 종류별 On/Off이고, 센서 임계값은 항목별 상·하한을 지정한다.

## 9. 안전 · 정지

> 성격이 다른 두 정지 기능을 구분한다. 배경과 표준 근거는 `non-functional.md` §2, 범위 구분표는 `../../00-overview.md` 참고.

### FR-35 원격 전체 정지
- 설명: 웹앱에서 대상 범위(전체 농장 또는 특정 농장)의 로봇·설비 작동을 정지시킨다. IEC 60204-1 **Stop Category 2**(제어된 정지, 전원 유지)에 해당하는 **운전 정지**이며, **안전등급 기능이 아니다.**
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고:
    - 발동 시 확인 절차를 거친다 (오조작 방지).
    - 발동 중에는 **자동 스케줄 발행과 원격 제어 명령을 차단**하고, 화면 전체에 정지 중임을 표시한다.
    - **해제는 웹앱에서 가능하다.** 해제 권한 수준은 미정 (OPN-18).
    - 발동·해제 이력을 `StopEvent`로 기록한다 (발동자·시각·대상 범위·사유).
    - 이 기능을 "비상정지"로 표기하지 않는다.

### FR-36 물리 비상정지 상태 표시
- 설명: 현장의 물리 비상정지 장치(ISO 13850) 작동 상태를 웹앱에 표시한다.
- 담당 영역: 엣지 (장치 자체는 개발 범위 밖)
- 데이터소스: SIMULATED
- 비고:
    - **표시 전용이다. 웹앱에 해제 경로를 두지 않는다.** 물리 비상정지는 현장에서 의도적인 수동 조작으로만 리셋할 수 있다.
    - 작동 중임이 감지되면 원격 전체 정지(FR-35)와 시각적으로 구분되는 표시를 하고, "현장에서 직접 해제해야 함"을 안내한다.
    - **엣지가 상태를 발행해 주기로 확정되었다** (OPN-19 해소, `estop_state` 메시지 — `../03-architecture/communication-interface.md` §4.7). 2차년도 범위에서 진행한다.
    - 상태 변화 이력을 `StopEvent`로 기록한다.

### FR-37 통신 상태 감시·표시
- 설명: 엣지·센서·로봇의 온라인 여부와 마지막 수신 시각을 감시하고 표시한다.
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고:
    - MQTT **LWT(Last Will and Testament)** 와 birth/death 메시지, 그리고 마지막 수신 시각을 근거로 판정한다 (`../03-architecture/communication-interface.md`).
    - 판정 결과는 **온라인 / 응답 지연 / 오프라인** 3단계이며, 응답 지연·오프라인은 알림(FR-32)을 발생시킨다.
    - FR-08의 "센서 정상작동여부"를 이 기능으로 충족한다.
    - 통신 단절 시 미들웨어 서버는 자동 스케줄 발행을 보류한다 (`non-functional.md` 페일세이프).

## 10. 플랫폼

### FR-38 다농장 스코프 전환·전체 현황 집계
- 설명: 전체 농장 현황과 특정 농장 상세를 전환하며 조회한다.
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고: 전체 현황은 농장 수·상태 분포, 로봇 가동 대수, 당일 작업 건수, 미확인 알림 건수를 집계한다. 2차년도 실운영은 농장 1개이지만 UI·데이터 구조는 N개를 전제로 한다 (OPN-23).

### FR-39 센서 개별 관리·영점 보정
- 설명: 센서를 개별 개체로 등록·조회하고 영점 보정을 지시한다.
- 담당 영역: 공통
- 데이터소스: SIMULATED
- 비고:
    - 센서마다 식별자·유형·설치 위치·현재값·상태·마지막 수신 시각을 관리한다. 하나의 생육기(재배공간)에 같은 유형의 센서가 여러 대 분산 배치될 수 있으므로, **`device_id`+`sensor_type`만으로는 식별할 수 없고 센서 개별 식별자가 필요하다** (`../03-architecture/communication-interface.md`).
    - 영점 보정은 엣지로 전달되는 제어 명령이며, 보정 이력을 보존한다.

### FR-40 외부 기상 정보 연동·표시
- 설명: 외부 기상 API에서 농장 소재 지역의 기상 정보를 취득해 표시한다.
- 담당 영역: 외부
- 데이터소스: EXTERNAL
- 비고:
    - 표시 항목: 기온·날씨·습도·강수·풍속·일사량 수준.
    - **표시 및 참고 권고까지만 담당한다.** 기상 조건에 따른 환기·차광·천창 제어는 개발 범위 밖이다 (`../../00-overview.md` Out of Scope). 권고 문구는 제어 동작으로 오해되지 않게 표현한다.
    - 엣지가 아닌 외부 HTTP API에서 주기적으로 취득한다. 공급자는 미정 (OPN-17).
    - API 미연동·장애 시 해당 영역을 "정보 없음"으로 표시하고 다른 기능은 정상 동작해야 한다.

### FR-41 실시간 배치도
- 설명: 농장 내 랙·워크스테이션·탱크·센서·로봇의 위치를 도면 형태로 표시하고, 요소 선택 시 해당 상세로 이동한다.
- 담당 영역: HMI
- 데이터소스: SIMULATED
- 비고:
    - 로봇 위치는 실시간 갱신한다 (FR-04).
    - 좌표계의 원점·축 방향·단위·스케일 정의가 필요하며 엣지팀과 협의해야 한다 (OPN-21). 협의 전까지는 논리 배치(구역·슬롯 단위)로 표현하고 실좌표 렌더링은 보류한다.
    - 요소별 딥링크 대상: 로봇 → 로봇 상세, 센서 → 센서 상세, 탱크·워크스테이션 → 작업·공급 화면.
