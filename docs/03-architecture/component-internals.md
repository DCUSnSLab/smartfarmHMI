# 03-4 · 컴포넌트 내부 구성

`component-mapping.md`가 "기능(FR) 하나가 어느 컴포넌트 몫인지"를 다룬다면, 본 문서는 **컴포넌트 하나(웹앱/애플리케이션 서버/미들웨어 서버/엣지) 내부가 어떤 모듈로 이뤄지는지**를 다룬다.

## 1. 웹앱 (프론트엔드)

| 모듈 | 내용 |
|---|---|
| 화면(페이지) | 로그인, 전체 현황 대시보드, 농장 상세(상태·생육기·로봇·작업공급·알림), 통계·분석, 데이터 조회, 농업일지·메모, 알림, 음성/LLM UI, 지원, 설정(계정·장비·알림 규칙) |
| 스코프 관리 | 전체 ↔ 특정 농장 전환 상태 관리, 화면별 스코프 적용 (FR-38) |
| 실시간 데이터 클라이언트 | WebSocket 구독, 수신한 최신 데이터로 화면 갱신. 통신 상태·마지막 수신 시각 반영 |
| API 클라이언트 | REST 호출(조회·설정 변경), 애플리케이션 서버만 호출 (미들웨어 서버·브로커·엣지에는 직접 접근하지 않음) |
| 인증 상태 관리 | 로그인 토큰 보관, 라우트 가드(권한별 화면 접근 제어) |
| 알림 표시 모듈 | 전역 알림 패널, 미확인 건수, 심각도 표시, 딥링크 라우팅 (FR-33) |
| 정지 상태 표시 모듈 | 원격 전체 정지와 물리 비상정지를 **구분해** 전역 표시. 물리 비상정지에는 해제 경로를 두지 않는다 (FR-35·36) |
| 배치도 렌더러 | 랙·워크스테이션·탱크·센서 정적 배치 + 로봇 실시간 위치 렌더링, 요소 클릭 딥링크 (FR-41) |
| 접근성 모듈 | 글자 크기 3단계(글자·터치 영역 동시 확대, 설정 영속), 야외 고대비 모드 (`../01-requirements/non-functional.md` §5) |

## 2. 애플리케이션 서버

| 모듈 | 내용 |
|---|---|
| API 계층 (라우터/컨트롤러) | REST 엔드포인트, WebSocket 게이트웨이(웹앱에 데이터 푸시) |
| 인증/권한 모듈 | 로그인, 세션/토큰 발급·검증, 역할별 권한 검사, 2단계 인증, 원격 접근 허용 설정 (FR-31) |
| 비즈니스 로직 (서비스) | 메모 관리(FR-18), 장비 등록·관리(FR-07·13), 음성 기록 저장(FR-29) — 사용자가 직접 입력하는 내용 처리 |
| **내부 MQTT 구독자** | 미들웨어 서버가 재발행한 내부 토픽(`farmon-internal/v1/#`)을 구독해 웹앱으로 팬아웃. **엣지 원시 토픽은 구독하지 않는다** (설계 원칙 #2) |
| 미들웨어 서버 클라이언트 | 이력·통계·리포트·AI 분석·음성/LLM 결과 조회 요청, 제어 명령 전달 요청 (애플리케이션 서버는 엣지와 직접 통신하지 않는다) |
| 자체 저장소 | 계정, 세션, 메모 첨부파일 등 — 엣지 원시 데이터·통계·AI 분석 결과는 여기 두지 않는다 |

## 3. 미들웨어 서버

| 모듈 | 내용 |
|---|---|
| **MQTT 클라이언트 / 브로커** | 엣지 토픽 구독·명령 발행, 내부 토픽 재발행. 브로커를 내장할지 별도로 둘지는 미정 (OPN-22) |
| 엣지 통신 어댑터 | 엣지와의 프로토콜 처리. 2차년도는 임의 데이터 생성기, 이후 실제 엣지 구현체로 교체 (동일 토픽·스키마) |
| 데이터 수집기 | 센서·로봇 상태 수신, 시간 동기화(발생 시각 기준·수신 시각 병기), DB 적재. birth의 `metrics` 선언을 근거로 수집 대상 구성 |
| **내부 재발행기** | 수신 원시 데이터를 정규화해 내부 토픽으로 발행. 애플리케이션 서버가 구독하는 유일한 경로 |
| **오프라인 감지기** | LWT/death 메시지와 마지막 수신 시각으로 온라인·응답지연·오프라인 판정. 상태 전이 시 알림 발생, 자동 스케줄 발행 보류 (FR-37) |
| 커맨드 변환기 | 제어 요청을 엣지 명령으로 변환·발행. `command_id` 부여, ACK 대조, 타임아웃 처리, 멱등성 보장 |
| **정지 관리자** | 원격 전체 정지 발동·해제 발행, **정지 중 자동 스케줄·제어 명령 차단**, 물리 비상정지 상태 수신·재발행, 이력 저장 (FR-35·36) |
| 스케줄러 | 작업 스케줄(FR-19·20) 도달 시 파레트 임무 생성. 충돌 검사(로봇·워크스테이션·파레트), 정지 중·통신 단절 시 발행 보류 |
| **알림 엔진** | 수집 데이터·통신 상태를 알림 규칙과 대조해 알림 생성·저장·재발행 (FR-32~34) |
| 통계·리포트 엔진 | 저장된 원시 데이터로 통계 집계(FR-14), 조건 조회(FR-15), 농업일지 생성(FR-17, 일·주·월·년간) |
| AI·음성 연동 모듈 | 영상 기반 AI 분석(FR-09·12), 음성 인식/LLM 연동 훅(FR-27~30) — 엔진 자체는 미구현, 호출·결과 수신만 |
| **외부 기상 수집기** | 외부 기상 API 주기 조회·저장·재발행. 미연동·장애 시 다른 기능에 영향을 주지 않도록 격리 (FR-40) |
| 데이터 저장소 (DB) | 시계열 센서 데이터, 로봇 상태, 파레트·작업 임무 기록, 알림, 정지 이력, 기상 |
| 내부 조회 API | 애플리케이션 서버가 호출하는 REST API (외부 공개 없음) |

## 4. 엣지 (2차년도 한정 — 임의 데이터 생성기)

> **이 컴포넌트는 2차년도에 한정된 임시 구현이다.** 실제 엣지 실물이 없어 우리가 그 자리를 대신하는 시뮬레이터를 만드는 것이며, 실제 엣지(로봇·센서 실물, 3차년도 예정)의 개발은 우리 책임이 아니다. 미들웨어 서버가 노출하는 엣지 통신 인터페이스(MQTT 토픽·스키마)를 그대로 따르므로, 실제 엣지가 준비되면 이 컴포넌트를 통째로 교체하기만 하면 된다.

| 모듈 | 내용 |
|---|---|
| MQTT 클라이언트 | 브로커 접속, 텔레메트리·상태 발행, 명령 토픽 구독. **접속 시 LWT(death 토픽) 등록** |
| birth 발행기 | 접속 시 발행할 항목·타입·단위·초기값·주기를 선언 (`birth` 메시지) |
| 센서 데이터 생성기 | 온도·습도·조도·전력·탱크 수위 등 값을 주기적으로 생성해 발행 (랜덤 또는 패턴 기반, 필요시 이상값도 생성). **센서별 `sensor_id`를 부여해 개별 개체로 발행** |
| 로봇 상태 생성기 | 위치·속도·전원·충전 여부·임무 상태를 주기적으로 생성해 발행 |
| 파레트 임무 응답 시뮬레이터 | 파레트 작업 임무(FR-03, FR-19~26)를 받아 `ack`(accepted)를 즉시 반환하고, 일정 시간 뒤 `completed`(또는 의도적 `failed`) 응답을 돌려준다. **`command_id` 중복 시 재실행하지 않는다** |
| 정지 응답 시뮬레이터 | `remote_stop`/`remote_stop_release` 수신 시 작동 중단·재개를 모사. 물리 비상정지 상태(`estop_state`)도 임의로 발생시켜 표시 검증에 사용 |
| 페일세이프 모사 | 브로커 연결이 끊긴 상태를 모사해, 진행 중 임무를 안전 위치에서 정지·반납하고 신규 임무 수락을 중단하는 동작을 검증 |
