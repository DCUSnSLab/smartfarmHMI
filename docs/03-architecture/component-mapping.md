# 03-3 · 컴포넌트별 세부 책임

`system-architecture.md`가 서버 2개(애플리케이션 서버, 미들웨어 서버)의 전체 구조를 다룬다면, 본 문서는 **기능(FR) 하나하나를 웹앱·애플리케이션 서버·미들웨어 서버 중 누가 무엇을 구현하는지** 실제 개발 시 참고할 수 있도록 정리한 것이다.

영상 기반 AI 분석(FR-09·12), 통계·리포트 생성(FR-14·17), 음성·LLM 연동(FR-27·30)은 **미들웨어 서버**가 처리한다. 필요한 원시 데이터(영상, 센서 이력)가 이미 미들웨어 서버 DB에 있어 그 자리에서 처리하는 것이 자연스럽고, 애플리케이션 서버는 그 결과를 웹앱에 전달하는 역할만 한다.

## 1. 로봇 제어

| FR | 웹앱 | 애플리케이션 서버 | 미들웨어 서버 |
|---|---|---|---|
| FR-01 로봇 작업데이터 로깅 | 작업 이력 조회 화면 | 이력 조회 API (미들웨어 서버에 요청) | 엣지로부터 이력 수신·저장(DB) |
| FR-02 다중 로봇 제어 | 제어 요청 UI | 요청 검증·권한 확인 후 미들웨어 서버에 위임 | 명령 규격화 후 엣지 전달 |
| FR-03 로봇임무 스케줄링 | 임무 등록/조회 UI | 임무 등록 API, 저장 위임 | 임무를 엣지 실행 요청(파레트 반출-이동-반납)으로 변환, 실행 상태 추적 |
| FR-04 로봇상태 모니터링 | 대시보드 표시 (WebSocket 구독) | 최신 상태 조회/푸시 API | 엣지로부터 상태 수신·저장 |
| FR-05 로봇 센서데이터 로깅 | 영상 조회 UI | 조회 API | 영상 메타데이터 수신·저장 |
| FR-06 로봇 자동충전기능 | 충전 지시 UI | 지시 API | 엣지에 전달 |
| FR-07 로봇 추가/삭제 | 등록 관리 UI | 등록/삭제 API, 장비 메타 관리 | 제어 시 참조할 장비 메타 저장 |
