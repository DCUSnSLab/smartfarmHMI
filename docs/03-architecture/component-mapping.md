# 03-3 · 컴포넌트별 세부 책임

`system-architecture.md`가 서버 2개(애플리케이션 서버, 미들웨어 서버)의 전체 구조를 다룬다면, 본 문서는 **기능(FR) 하나하나를 웹앱·애플리케이션 서버·미들웨어 서버 중 누가 무엇을 구현하는지** 실제 개발 시 참고할 수 있도록 정리한 것이다.

영상 기반 AI 분석(FR-09·12), 통계·리포트 생성(FR-14·17), 알림 생성(FR-32), 음성·LLM 연동(FR-27·30), 외부 기상 수집(FR-40)은 **미들웨어 서버**가 처리한다. 필요한 원시 데이터(영상, 센서 이력)가 이미 미들웨어 서버 DB에 있어 그 자리에서 처리하는 것이 자연스럽고, 애플리케이션 서버는 그 결과를 웹앱에 전달하는 역할만 한다.

> **공통 사항** — 모든 기능은 농장 단위로 동작한다. 웹앱은 스코프(전체/특정 농장)에 따라 대상을 좁히고, 애플리케이션 서버는 요청에 농장 식별자를 포함해 위임하며, 미들웨어 서버는 농장별 토픽·데이터로 처리한다 (FR-38). 아래 표에서 농장 스코프 처리는 개별 언급을 생략한다.
>
> 실시간 데이터는 **미들웨어가 내부 MQTT 토픽으로 재발행 → 애플리케이션 서버가 구독 → 웹앱에 WebSocket 푸시** 경로를 따르고, 이력·설정은 **웹앱 REST → 애플리케이션 서버 → 미들웨어 내부 REST** 경로를 따른다. 아래에서 "조회/푸시 API"는 이 경로를 가리킨다.

| FR-06 로봇 자동충전기능 | 충전 지시 UI, 충전 상태·완충 예상 표시 | 지시 API | 엣지에 명령 발행, 충전 상태 수신 |
