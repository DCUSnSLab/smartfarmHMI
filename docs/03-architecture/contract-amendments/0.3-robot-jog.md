# 계약 개정 0.3 · 로봇 이동 조작 (robot_jog)

GEN-1297. `communication-interface.md` §4 에 메시지 1종을 **추가**한다. 원본은 수정하지
않고 §4 에 pointer 만 둔다 — 여러 브랜치가 같은 문서를 동시에 고치므로 개정 본문을
분리한다. develop 머지 시점에 원본에 접어 넣는다.

근거: `../../design/design-change-spec.md` §5 항목 2 가 남겨둔 결정, `../../01-requirements/functional.md` §11.

## 0. 버전을 올리지 않는 이유

**순수 추가다.** 기존 메시지의 필드도 의미도 하나 바뀌지 않는다. 0.3 을 아는 수신자는
`robot_jog` 를 모를 뿐 나머지는 그대로 해석한다.

버전을 0.4 로 올리면 `conformance.py` 가 minor 불일치로 판정해, 아직 0.3 인 virtual-edge
와 기존 엣지가 보내는 **모든** 메시지에 경고가 붙는다. 얻는 것 없이 로그만 오염된다.
버전은 필드나 의미가 바뀔 때 올린다.

## 1. 범위 경계 — 무엇이 들어오고 무엇이 남는가

`functional.md` §11 은 "웹앱 기반 로봇 원격조종기(로봇팔 직접 조작)"를 2차년도 제외
항목으로 둔다. 이 개정은 그 경계를 **좁혀서 확정**한다.

| | 범위 |
|---|---|
| 로봇 **이동** 조작 (전·후·좌·우·정지) | **안** — 이 개정 |
| 로봇**팔** 직접 조작 | 밖 (제외 항목 유지) |
| 연속 조종 + 영상 (본격 텔레오퍼레이션) | 밖 — 3.4 참고 |

이동 조작은 화면 설계(수동 제어 모달)에 처음부터 자리가 있었고, 임무 실패로 로봇이
어중간한 곳에 멈췄을 때 사람이 빼내는 수단이 달리 없다. 제외 항목이 겨냥한 것은
로봇팔 조작이라는 별도 R&D 과제이지 주행이 아니다.

## 2. 미들웨어 → 엣지: 이동 조작 (robot_jog)

토픽 `farmon/v1/{farm}/robot/{robot_id}/command`, **QoS 1 · retain 금지**.

```json
{
  "type": "robot_jog",
  "version": "0.3",
  "command_id": "cmd-3f0a91b2c4d5",
  "farm_id": "seongju",
  "device_id": "robot-01",
  "direction": "forward",
  "speed": 0.6,
  "duration_ms": 800,
  "issued_by": "user-42",
  "timeout_sec": 2,
  "timestamp": "2026-08-11T10:00:00+09:00"
}
```

| 필드 | 의미 |
|---|---|
| `direction` | `forward` \| `backward` \| `left` \| `right` \| `stop` |
| `speed` | **0.0~1.0 정규화 비율.** m/s 가 아니다 — 3.2 참고 |
| `duration_ms` | 데드맨. 이 시간이 지나면 엣지가 **스스로** 0 속도를 낸다 — 3.1 |

`stop` 은 `speed`·`duration_ms` 를 무시하고 즉시 정지한다.

## 3. 설계 근거

### 3.1 데드맨 — 정지는 도착하지 않을 수 있다

MQTT 는 유실·지연된다. "정지 명령이 도착해야 멈춘다"로 설계하면 **정지 메시지 하나가
유실됐을 때 로봇이 계속 간다.** 브로커·네트워크·엣지 프로세스 중 하나만 흔들려도
그렇게 된다.

그래서 정지의 근거를 메시지 도착이 아니라 **시간 경과**에 둔다. 명령 하나는
`duration_ms` 동안만 유효하고, 그 뒤 엣지가 스스로 0 속도를 낸다. 웹은 버튼을 누르고
있는 동안 그보다 짧은 주기로 명령을 반복해 이어 붙인다.

```
발행    ├──400ms──┼──400ms──┼──400ms──┤ (버튼 뗌)
유효구간 ├────800ms────┤
              ├────800ms────┤
                    ├────800ms────┤
                                  └─ 마지막 명령 만료 → 자동 정지
```

반복이 끊기면 최대 `duration_ms` 뒤 멈춘다. 통신이 죽어도, 브라우저 탭이 닫혀도,
조작자가 쓰러져도 같다. `stop` 은 그보다 빨리 멈추기 위한 것이지 **멈춤의 유일한
근거가 아니다.**

`duration_ms` 는 반복 주기보다 길고(끊김 없이 이어지도록) 사람의 반응 시간보다
짧아야(뗐을 때 곧 서도록) 한다. 서버가 100~2000ms 로 강제한다.

### 3.2 speed 가 m/s 가 아닌 이유

웹도 미들웨어도 로봇의 물리적 상한을 모른다. 농장마다 기종이 다르고, 같은 기종도
적재 상태에 따라 다르다. m/s 를 서버가 정하면 **서버가 모르는 값을 강제**하게 된다.

정규화 비율을 보내고 상한은 엣지가 소유한다. 엣지는 자기 설정의 `jog_linear_mps`·
`jog_angular_rps` 에 비율을 곱한다. 서버는 비율을 0.0~1.0 으로 자르는 일만 한다 —
서버가 아는 범위 안에서만 강제한다.

### 3.3 임무 중 조작 — 임무를 접고 사람을 따른다

`design-change-spec.md` §5 항목 2 가 명세를 요구한 인터록이다.

임무(`pallet_task`) 진행 중 jog 가 오면 **임무를 취소하고 jog 를 받는다.** 사람이
수동 조작에 손을 댔다는 것은 자동이 원하는 대로 가지 않고 있다는 뜻이고, 그 상황에서
자동을 계속 우선하면 사람이 로봇을 빼낼 방법이 없다.

취소된 임무는 `failed` 로 ack 하고 `detail.reason = "manual jog override"` 를 싣는다.
"완료"로 접으면 하지 않은 일을 했다고 기록하는 것이고, 조용히 지우면 임무가 왜
사라졌는지 아무 데도 남지 않는다.

취소는 임무를 **되돌리지 않는다.** 파레트가 이미 들려 있으면 들린 채로 멈춘다 —
원격에서 안전하게 되돌릴 방법이 없고, 사람이 이미 현장 판단을 하고 있는 상황이다.

### 3.4 영상은 이 계약에 실리지 않는다

버튼식 이동 조작은 단발 명령이라 MQTT 로 충분하다. 영상을 보며 연속 조종하는 본격
텔레오퍼레이션은 다른 문제다 — 지연 예산이 수십 ms 단위이고, QoS 1 의 중복 배달과
ack 왕복이 오히려 방해가 된다. 별도 실시간 채널(WebRTC 등)이 필요하다.

이 개정은 그쪽을 **막지 않는다.** `robot_jog` 는 "한 번의 조작 의도"만 담고 세션·
스트림 개념을 넣지 않았으므로, 나중에 실시간 채널이 생겨도 이 메시지는 그대로 두고
그 위에 얹으면 된다.

## 4. 차단 — 어디서 막는가

원격 전체 정지(§4.6) 또는 물리 비상정지(§4.7) 중에는 jog 를 **미들웨어가 거부**한다
(HTTP 423). 화면 비활성화에 의존하지 않는다 (`non-functional.md` §2.3).

엣지도 `state_.stopped` 면 거부한다. 두 곳 모두에서 막는 것은 중복이 아니다 —
미들웨어를 거치지 않고 브로커에 직접 발행된 명령이 있을 수 있다.

## 5. ack

엣지는 다른 명령과 같은 형식으로 ack 한다. 다만 **미들웨어는 jog 를 `command_log` 에
남기지 않으므로**(6절) ack 는 매칭되지 않고 버려진다. 기존 동작과 같다 — 서버 밖에서
발행된 명령의 ack 도 같은 이유로 버려진다.

거부 사유가 조작자에게 닿아야 하는 경우는 4절에서 미들웨어가 먼저 막으므로 HTTP
응답으로 전달된다.

## 6. 이력을 남기지 않는 이유, 그리고 남은 일

`command_log` 는 **명령 한 건의 생명주기**(발행 → ack → 종결)를 담는 자리다. jog 는
누르고 있는 동안 초당 수 건이 나가는 연속 조작이라 1:1 로 넣으면 이력이 jog 로
뒤덮이고, `timeout_watcher` 가 매 건을 감시하게 된다.

이번 범위에서는 남기지 않는다. 미들웨어가 발행을 INFO 로그로 남기고 실시간 스트림
으로 화면에 보낸다.

**남은 일**: "누가 언제 로봇을 수동으로 움직였나"는 안전 관련 기록이라 결국 필요하다.
명령 단위가 아니라 **조작 세션 단위**(시작·종료·방향·조작자)로 남기는 별도 테이블이
맞는 모양이다. 이 개정의 범위 밖이다.
