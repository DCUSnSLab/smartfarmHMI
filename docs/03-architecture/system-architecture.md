# 03-1 · 시스템 아키텍처

서버는 1개가 아니라 역할이 다른 **애플리케이션 서버**와 **미들웨어 서버** 2개로 나뉜다. 엣지 원시 데이터(센서·로봇 상태 등)는 미들웨어 서버에 저장되고, 계정·세션·메모처럼 사용자가 직접 입력하는 데이터는 애플리케이션 서버에 저장된다 (두 저장소를 물리적으로 분리할지는 `component-internals.md` 참고).

기능(FR)별로 두 서버와 웹앱이 각각 무엇을 담당하는지는 `component-mapping.md`, 각 컴포넌트 내부 구성은 `component-internals.md`, 통신 규격은 `communication-interface.md`에서 다룬다.

## 1. 계층 구조

| 계층 | 구성 요소 | 통신 대상 (프로토콜) |
|---|---|---|
| 웹앱 (브라우저) | 모니터링 대시보드, 제어 UI, 데이터 관리, 알림, 음성/LLM UI | 애플리케이션 서버 (**WebSocket + REST**) |
| **애플리케이션 서버** | 인증·세션, 관리자 메모·장비등록 등 사용자 입력 처리, 미들웨어 서버 결과를 웹앱에 전달하는 API/WebSocket 게이트웨이, 웹앱 서빙 | 웹앱, 미들웨어 서버 (**내부 MQTT 구독 + REST**) |
| **미들웨어 서버** | 엣지 데이터 수집·저장(DB), 통계·농업일지 생성, 알림 엔진, 영상 기반 AI 분석·음성 처리·LLM 연동 훅, 제어 명령 변환, 외부 기상 수집 | 애플리케이션 서버, MQTT 브로커 |
| **MQTT 브로커** | 엣지↔미들웨어 구간과 미들웨어→애플리케이션 서버 내부 구간의 메시지 중계 | 미들웨어 서버, 애플리케이션 서버, 엣지 |
| 엣지 | 실물 하드웨어와의 통신, ROS2↔MQTT 브리지 (2차년도는 임의 데이터 생성기, 3차년도 예정: 실제 엣지) | MQTT 브로커 (**MQTT**) |
| 외부 시스템 | 기상 API, 음성 인식 엔진, LLM | 미들웨어 서버 (**HTTP 등**) |

엣지 하위의 로봇·생육기 등 실물 하드웨어, 로봇 경로계획, AI 모델, 음성 인식 엔진, 물리 비상정지 장치는 개발 범위 밖이다.

브로커를 미들웨어 서버에 내장할지 별도 프로세스·호스트로 둘지, 인증·TLS를 어떻게 구성할지는 미정 (OPN-22).

## 2. 계층별 동작 방식

### 웹앱 ↔ 애플리케이션 서버
- 화면 갱신은 WebSocket으로 애플리케이션 서버가 푸시하는 최신 데이터를 받는다.
- 설정 변경·조회는 REST로 처리한다.

### 애플리케이션 서버
- 사용자 인증·권한을 관리한다.
- 관리자 메모 작성, 장비 등록·관리 등 사용자가 직접 입력하는 내용을 처리한다.
- 미들웨어 서버가 만든 결과(통계, 리포트, AI 분석 결과, 알림 등)를 웹앱이 원하는 형태로 전달하는 API/WebSocket 게이트웨이 역할을 한다.
- **실시간 데이터는 미들웨어 서버가 재발행한 내부 MQTT 토픽을 구독해 받고**, 이를 웹앱에 WebSocket으로 팬아웃한다. 과거 데이터·설정은 미들웨어 서버의 내부 REST API로 조회한다.
- 웹앱을 서빙한다.

### 미들웨어 서버
- 엣지가 주기적으로 발행하는 데이터를 MQTT로 수신·저장(DB)한다. 센서값 하나하나를 즉시 애플리케이션 서버까지 중계하는 것이 아니라, 미들웨어 서버가 중간에서 저장·버퍼 역할을 한다.
- 수신한 원시 데이터를 정규화해 **내부 토픽으로 재발행**한다. 애플리케이션 서버는 이 내부 토픽만 구독한다.
- 통계 집계, 농업일지 생성, 알림 생성, 영상 기반 AI 분석, 음성 처리, LLM 연동 등 **원시 데이터를 다루는 처리**를 담당한다. 이 데이터가 이미 미들웨어 서버 DB에 있으므로, 별도 서버로 옮기지 않고 여기서 처리한다.
- 외부 기상 API를 주기적으로 조회해 저장하고 내부 토픽으로 재발행한다 (FR-40).
- 애플리케이션 서버를 거쳐 들어온 제어 요청을 규격화된 명령으로 변환해 엣지로 발행한다.
- **장치 통신 상태를 감시한다.** LWT/death 메시지와 마지막 수신 시각으로 온라인·응답지연·오프라인을 판정한다 (FR-37).
- **원격 전체 정지 발동 중에는 자동 스케줄 발행과 제어 명령 전달을 차단한다** (FR-35). 차단은 웹앱 UI 비활성화에 의존하지 않고 여기서 수행한다.

### 엣지
- 2차년도에는 임의 데이터 생성기로 대체한다. 데이터를 주기적으로 발행하고, 미들웨어 서버의 제어 명령을 받아 실행하는 역할을 한다.
- 트레이(파레트) 반출·이동·작업·반납(로봇 임무)과 생육기 환경 제어를 포함한다.
- **로봇 내부가 ROS2를 사용하더라도 미들웨어 서버와는 MQTT로 통신한다.** 엣지가 ROS2↔MQTT 브리지 역할을 맡으며, 이 변환은 엣지 내부 관심사다 (범위 밖).
- 통신이 끊기면 진행 중 임무를 안전한 위치에서 정지·반납하고 신규 임무 수락을 중단한다 (페일세이프 ①계층 — 범위 밖이지만 인터페이스 계약으로 명시).

## 3. 설계 원칙

1. 모든 외부 하드웨어는 엣지를 통해서만 미들웨어 서버와 통신한다.
2. **애플리케이션 서버는 미들웨어 서버를 통해서만 엣지 데이터에 접근한다.** 애플리케이션 서버는 브로커에 접속하지만, **엣지가 발행하는 원시 토픽을 직접 구독하지 않고 미들웨어 서버가 정규화해 재발행한 내부 토픽만 구독한다.** 브로커를 공유하더라도 이 원칙은 토픽 네임스페이스 분리와 구독 권한(ACL)으로 보장한다 (`communication-interface.md`).
3. 엣지와의 통신은 인터페이스로 분리한다. 2차년도에는 임의 데이터 생성기 구현체를 연결하고, 이후 실제 엣지 구현체로 교체 가능해야 한다. 임의 데이터 생성기와 실제 엣지는 **동일한 토픽·스키마**를 사용한다.
4. 데이터·명령 규격은 특정 필드 집합에 고정하지 않고, 확장 가능한 구조로 설계한다. 장치가 birth 메시지로 자신의 데이터 항목을 선언한다.
5. **안전 기능을 MQTT 경로에 의존시키지 않는다.** MQTT는 안전등급 통신이 아니다. 실제 비상정지는 현장 물리 장치가 담당하고, 웹앱→엣지 경로의 정지는 운전 정지(Stop Category 2)로 정의한다 (`../01-requirements/non-functional.md` §2).

```
                     ┌─────────────────────────────────┐
   웹앱 ◀── WS/REST ──│      애플리케이션 서버           │
                     └───────┬──────────────▲──────────┘
                 내부 MQTT 구독│              │REST (이력·설정)
                             │              │
                     ┌───────▼──────────────┴──────────┐
                     │        미들웨어 서버              │──▶ 외부 기상 API
                     │  수집·저장 · 정규화·재발행        │
                     │  통계 · 알림 · AI/음성 훅        │
                     └───────┬──────────────▲──────────┘
                     명령 발행 │              │ 텔레메트리·상태·birth/death
                     ┌───────▼──────────────┴──────────┐
                     │          MQTT 브로커             │
                     └───────┬──────────────▲──────────┘
                             │              │
                     ┌───────▼──────────────┴──────────┐
                     │       엣지 통신 인터페이스        │
                     │      (ROS2 ↔ MQTT 브리지)        │
                     ├─────────────────────────────────┤
                     │ 2차년도: 임의 데이터 생성기       │
                     │ 3차년도: 실제 엣지 (예정)         │
                     └─────────────────────────────────┘
```

## 4. 확정된 사항

- **미들웨어 서버 ↔ 엣지: MQTT** (OPN-01 해소). 로봇 내부 ROS2는 엣지가 브리지한다
- **애플리케이션 서버 ↔ 미들웨어 서버: 내부 MQTT 구독(실시간) + REST(이력·설정)** (OPN-12 해소)
