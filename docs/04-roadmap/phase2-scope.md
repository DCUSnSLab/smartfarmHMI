# 04-1 · 2차년도 로드맵과 현재 개발 범위

## 1. 일정 제약

- 스마트팜 실물 세팅이 **8월** 완료 예정
- 로봇공학과 결과발표는 **2027년 1월**
- 따라서 우리 담당 기능 개발은 **8월까지 끝내고**, 이후에는 실제 엣지로 교체·연동 검증을 진행한다.

기능 수는 사업단 제공 31개(FR-01~31)에 자체 도출 10개(FR-32~41)를 더해 **총 41개**다. 자체 도출분은 알림 3건, 안전·정지 3건, 플랫폼 4건으로, 대부분 디자인 프로토타입이 이미 화면으로 다루고 있던 항목이다.

## 2. 2차년도 데모 목표

- 음성 인식을 통한 식물공장 제어
- 웹앱을 통한 식물공장 제어

상세 시나리오는 아직 확정되지 않았다 (OPN-11).

## 3. 운영 전제

**설계·구현은 농장 N개를 전제로 하고, 2차년도 실운영은 농장 1개로 진행한다(테스트).** 웹앱 UI도 다농장 기준으로 만든다. 데이터 모델과 MQTT 토픽이 모두 농장 단위로 계층화되어 있으므로, 농장을 추가할 때 스키마·토픽 구조를 바꾸지 않는다. 실운영 전환 시점은 미정 (OPN-23).

## 4. 2차년도 로드맵

시스템 기반 설계 및 핵심 구현

**5~6월 : 시스템 아키텍처 설계**
- **통신 프로토콜 정의 — MQTT 확정** (엣지 구간). 로봇 내부가 ROS2를 쓰더라도 엣지가 ROS2↔MQTT 브리지를 담당한다
- **내부 구간 정의 — 애플리케이션 서버는 미들웨어가 재발행한 내부 MQTT 토픽 구독 + 이력은 REST**
- 토픽 네임스페이스·QoS·retained·LWT 정책 확정
- DB 스키마 설계 (센서·영상·로봇·생육·알림·정지)
- 제어 API 명세 (타 연구실 인터페이스 합의)

**7~8월 : 백엔드 코어 + 엣지 개발**
- 미들웨어 서버 프레임워크 구축 (MQTT 클라이언트, 수집기, 내부 재발행기)
- 엣지 시뮬레이터: MQTT 클라이언트 + LWT·birth 발행 + 디바이스 매니저
- 센서/시설 드라이버 + 데이터 버퍼 구현
- **오프라인 감지기·알림 엔진·정지 관리자 구현** (FR-32·35·37)

**9~10월 : 프론트엔드 + 음성인식 모듈**
- 모니터링 대시보드 MVP (환경 데이터)
- 생육기 수동제어 UI + 음성인식 엔진 통합
- **알림 화면·정지 상태 표시·접근성(글자 크기 3단계) 구현**
- 엣지-미들웨어 데이터 동기화 테스트

**11~1월 : 통합 테스트 + 데모**
- 식물공장 모듈 연동 (엣지→미들웨어→웹앱)
- 데모: 음성/웹앱 → 식물공장 제어
- **페일세이프 검증** — 통신 단절 시 임무 정지·자동 스케줄 보류·화면 표시 동작 확인
- 안전 감시 모듈 기초 구현

## 5. 현재 개발 범위

1. **임의 센서/로봇상태 데이터 생성기 구현** — `../03-architecture/communication-interface.md`의 MQTT 토픽·메시지 스키마 기준. 센서별 `sensor_id` 부여, 접속 시 `birth` 발행, LWT 등록 포함
2. **미들웨어 서버가 데이터를 수신·저장** (FR-01, FR-04, FR-08, FR-16) — 발생 시각 기준 시간 동기화, 수신 시각 병기
3. **애플리케이션 서버·웹앱에서 데이터 조회 화면 구현** (FR-08 생육환경 모니터링, FR-04 로봇상태 모니터링 우선) — 실시간은 내부 MQTT 구독 → WebSocket 푸시 경로로
4. **통신 상태 감시** (FR-37) — LWT 기반 오프라인 감지. 1~3의 흐름을 검증하는 과정에서 함께 확인할 수 있어 초기에 넣는다

이 흐름이 검증되면 제어 명령 방향(웹앱 → 애플리케이션 서버 → 미들웨어 서버 → 엣지, FR-10 등)으로 확장하고, 이어서 알림(FR-32~34)·정지(FR-35·36)와 나머지 기능을 진행한다. 제어 방향에서는 `command_id` 멱등성과 ACK·타임아웃 처리를 함께 구현한다.
