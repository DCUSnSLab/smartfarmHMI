## 1. 정지 UI 이원화 (FR-35 · FR-36) — 신규 설계

현재 프로토타입은 정지 배너가 1종뿐이다. **성격이 다른 두 상태를 각각 표시해야 하며, 동시에 성립할 수 있다.**

| | 원격 전체 정지 (FR-35) | 물리 비상정지 (FR-36) |
|---|---|---|
| 표준 | IEC 60204-1 Stop Category 2 (운전 정지) | ISO 13850 |
| 안전등급 | **비안전등급** | 안전 기능 |
| 발동 주체 | 웹앱 사용자 | 현장 작업자 (물리 장치) |
| 해제 | **웹앱에서 가능** | **현장 수동 조작만 — 웹앱에 해제 버튼을 두지 않는다** |
| 담당 | 우리 팀 (범위 내) | 엣지·하드웨어팀 (범위 밖) |

### 필요 작업

1. **배너 2종 분리** — 배너는 **표시 전용**, 조작은 상단 네비의 정지 자리 (GEN-1228 변경)
   - 원격 전체 정지 배너: 발동자·경과 시간 표시. **해제 버튼은 배너에 두지 않고** 네비의 발동 버튼과 같은 자리에 둔다 — 정지 중 그 자리가 비면 우측 구성이 무너지고, 배너·네비 두 곳의 버튼 폭을 맞추려 실측값을 박아야 한다
   - 물리 비상정지 배너: **신규.** 해제 경로 없음. "현장에서 직접 해제해야 합니다" 안내 문구 포함
   - 두 상태가 동시에 성립할 수 있으므로 배너가 겹쳐 쌓인다 (물리가 위 — 상위 심각도)
   - 배너는 헤더와 함께 고정되므로 **높이가 곧 본문 손실**이다. 어느 폭에서도 한 줄로 접고 상세는 셰브론으로 펼친다
2. **시각적 구분** — 색으로만 구분하지 않는다 (접근성 요구사항). 아이콘·문구·테두리를 함께 달리한다. 물리 비상정지가 상위 심각도이므로 더 강한 표현을 배정하는 것을 권한다 (예: 물리=적색 실선 강조, 원격=주황 계열)
3. **상단 버튼** — 원격 전체 정지 버튼만 둔다. 물리 비상정지는 발동 수단이 웹앱에 없으므로 버튼을 만들지 않는다
4. **상태 취득 경로 확정** — 엣지가 `estop_state`를 발행해 주기로 확정되었다 (OPN-19 해소). 배너 2종은 2차년도 범위에서 모두 설계한다. 단, 엣지 통신 단절 중에는 "상태 미확인"으로 표시하지 말고 통신 단절 표시(FR-37)로 대신한다 — 잘못된 안심을 주지 않기 위함이다

## 4. 생육기 단위 UI 자체 설계안 (OPN-16 — 확정 보류)

### 문제

요구사항 다수(FR-08·10·11·14·19·21~26)가 **"생육기별"** 을 전제한다. 그런데 현재 「농장 상세 · 생육기·센서」 화면은 **농장당 재배공간 1개**를 전제로 센서 8대를 공간 전체로 집계한다. 동시에 설정 화면은 같은 농장에 "생육기 3 / 4 / 6"이라고 표시한다 — **디자인 내부에서 모순**이다.

### 제안 (판단 보류)

**생육기 선택 축을 화면 상단에 추가하고, 기본값을 「전체 집계」로 둔다.**

```
농장 상세 · 생육기·센서
┌──────────────────────────────────────────────┐
│ [전체 집계] [A동 베드1] [A동 베드2] [B동 랙1] │ ← 생육기 선택 (세그먼트/칩)
└──────────────────────────────────────────────┘
  · 전체 집계 선택 시: 현재 화면 그대로 (농장 내 센서 집계)
  · 개별 생육기 선택 시:
      - 실시간 환경값 → 해당 생육기 소속 센서만 집계
      - 환경 제어      → 해당 생육기 대상으로 명령
      - 센서 목록      → 해당 생육기 소속 센서만
      - 생육 상태(AI)  → 해당 생육기 영상 분석 결과
```

**이 방식을 제안하는 이유**
- 기존 화면 구조를 유지하면서 축 하나만 추가하므로 변경 범위가 작다
- 「전체 집계」를 기본값으로 두면 농장에 생육기가 1개일 때(2차년도 초기) 현재와 동일하게 보인다
- FR-10·11의 제어 대상이 명확해진다 (현재는 "무엇을 제어하는지" 화면상 불분명)

**함께 결정해야 할 것**
- 생육기가 많아질 때(설정 화면 기준 최대 6개) 세그먼트가 넘치는 경우의 처리 — 드롭다운 전환 기준
- 통계 화면(FR-14)의 대상 축에도 같은 선택기를 넣을지
- LED 제어 단위와의 관계 — 2차년도는 그룹/전체 제어이므로 생육기 단위와 어긋날 수 있음 (OPN-14)

| 1 | `.dc.html` `applyFarm()` 내 `set('[data-farmname]', f.name)` | **`data-farmname` 속성을 가진 요소가 문서에 없다.** 농장 전환 시 농장명 갱신이 동작하지 않는 dead code. 스코프 스위처 칩이 이름을 보여주므로 화면상 드러나지 않는다. 농장명을 표시할 요소를 추가하거나 호출을 제거할 것 |
| 2 | `data-jog` 요소 5개 (수동 제어 모달의 이동·정지 버튼) | **클릭 핸들러가 없어 무동작.** 아울러 로봇 조작(jog)은 범위 경계가 모호하다 — `../../00-overview.md`가 "웹앱 기반 로봇 원격조종기(로봇팔 직접 조작)"를 범위 밖으로 두었다. 이동 조작을 유지할지 판단이 필요하며, 유지 시 "수동 제어 중 자동 스케줄 일시 중지" 인터록의 의미를 명세해야 한다 |
| 3 | `.dc.html` `conflictsFor()` | **임무 충돌 검사가 로봇 기준만이다.** 서로 다른 로봇을 같은 워크스테이션에 동시 예약할 수 있다. FR-03은 **로봇·워크스테이션·파레트 3자원** 충돌 검사를 요구한다 |

## 6. 구현 시 포팅 지침

| 항목 | 현재 프로토타입 | 구현 방향 |
|---|---|---|
| 스타일 | 인라인 스타일 약 186KB, 클래스 없음. 테마 전환을 `style` 속성 **문자열 치환**으로 처리 (`_applyProps()`의 `ACCENTS` 맵) | **CSS 커스텀 프로퍼티로 토큰화.** `README.md`의 디자인 토큰을 변수로 정의하고 마크업을 클래스 기반으로 재작성. 포팅 비용이 가장 큰 항목이며 가장 먼저 세워야 함 |
| 큰글씨 3단계 | `root.style.zoom = 1 / 1.16 / 1.34` | **rem 스케일로 전환.** `zoom`은 sticky 헤더·fixed 어시스턴트와의 상호작용이 취약하다. 루트 `font-size` 조정 + rem 기반 치수로 구현하고, 터치 영역이 함께 확대되는지 확인 → **이행 완료 (GEN-1246)**: 글자 크기를 `tailwind.config.ts` 의 `fontSize` 토큰(rem)으로 옮겨 배율이 글자에도 적용된다. 기준 크기는 16px 고정 (`../01-requirements/non-functional.md` §5) |
| 이벤트 | `document` 레벨 전역 위임 + `window.__pmv3` 1회성 가드, 해제 경로 없음 | 컴포넌트 스코프 이벤트로 재작성. SPA 라우팅에서 누수·중복 바인딩이 발생한다 |
| 상태 | `st = {screen, farm, tab}` + 모듈 스코프 `schedule[]` 배열 | 실제 상태 관리로 대체. 화면 전환은 `.scr[data-hidden]` 토글이 아니라 라우터로 |
| 접근성 | 색 + 도형 병기가 대체로 되어 있음 | 상태를 색으로만 구분하는 곳이 없는지 재확인 (`../01-requirements/non-functional.md` §5) |
